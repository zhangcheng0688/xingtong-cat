# 星童猫咪 · 微信小程序正式部署手册

目标：把当前产品以「星童猫咪」小程序正式上架微信。本手册分三部分——
**A. 你需要做的事**（账号与资质，只有主体本人能办）· **B. 技术迁移方案**（我来执行）· **C. 上线时间线与费用**。

---

## A. 你需要做的事（按顺序，共 6 步）

### A1. 注册小程序账号 —— 主体必须选「企业」或「个体工商户」

前往 [mp.weixin.qq.com](https://mp.weixin.qq.com) → 立即注册 → 小程序。

⚠️ **不要用个人主体**。微信官方明确规定：手机号快速验证组件「针对非个人开发者，且完成了认证的小程序开放」
（[微信官方文档](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/deprecatedGetPhoneNumber)）。
个人主体注册后再迁移主体是独立且耗时的流程，一步到位最省事。

准备材料（[参考](https://blog.csdn.net/qq_54239496/article/details/143228680)）：
- 一个未注册过微信公众平台/开放平台、未绑定个人微信的邮箱
- 营业执照（18 位统一社会信用代码）
- 管理员姓名、身份证、手机号（短信 + 扫码验证）
- 主体验证二选一：对公账户小额打款验证（免费，10 天内完成）或微信认证（300 元/年）

### A2. 完成微信认证（300 元/年）

「手机号快速验证」等关键能力要求**已认证**的小程序。认证审核 1~5 个工作日。
如果 A1 选了打款验证，这里仍需单独完成认证才能开通手机号组件
（[参考](https://www.cnblogs.com/QuestionsZhang/p/19153896)）。

### A3. 选择服务类目 —— 走「教育」，避开「医疗」

这是最关键的合规决策。我们的产品文案与定位是**家庭教育支持**，
应避免「诊断 / 治疗 / 康复」等医疗宣称：

| 路线 | 类目 | 资质要求 | 结论 |
|---|---|---|---|
| ✅ 推荐 | 教育（教育信息服务 / 在线教育类） | 无需医疗资质 | 与「家庭干预学习」定位一致 |
| ❌ 避免 | 医疗（就医服务 / 互联网医院等） | 《医疗机构执业许可证》、卫健委批文、合作协议等（[微信官方类目文档](https://developers.weixin.qq.com/minigame/product/material/)） | 我们没有医疗机构资质，且与产品定位不符 |

对应地，产品内已有免责声明「本产品是家庭教育支持工具，不构成医疗诊断或治疗建议」，上线审核时保持该口径。

### A4. 开通「手机号快速验证」组件
企业主体 + 微信认证完成后，在 mp 后台「设置 - 接口权限」启用。
费用（[微信官方文档](https://developers.weixin.qq.com/community/develop/article/doc/000c8c53920058de3dfffd33f56813)）：

- 每个小程序有 **1000 次体验额度**
- 超出后：快速验证 **0.03 元/次**，实时验证 0.04 元/次（2023-08-26 起收费）

登录方案因此设计为：**微信无感登录为主（免费、零摩擦），手机号绑定为辅（按需触发）**——
先 wx.login 换 openid 直接登录进产品，仅在需要账号找回/通知触达时才请用户验证手机号，
避免被微信判定「不合理要求用户提供手机号」（可能导致接口权限被回收）。

### A4b. 申请微信支付商户号 + 注意 iOS 虚拟支付限制（积分充值必读）

积分充值属于**虚拟商品**，有两条硬性规则：

1. **微信支付商户号**：前往 [pay.weixin.qq.com](https://pay.weixin.qq.com) 用同一企业主体申请商户号
  （营业执照 + 法人身份证 + 对公账户），审核通过后与小程序 AppID 绑定，即可使用
  `wx.requestPayment` 调起支付。技术侧已预留：Web 版积分中心（`/billing`）的购买接口语义
  与小程序支付回调完全对齐——用户支付成功 → 微信回调 → 服务端验签 → 积分到账。
2. **iOS 端虚拟支付禁令**：微信小程序在 iOS 上**禁止虚拟商品支付**（积分、会员、课程均属此类），
  只有 Android 可以正常调起微信支付。行业通行做法：
   - iOS 端隐藏「充值」入口，引导语改为「请使用安卓设备充值」或引导至公众号 H5 完成支付；
   - 积分余额、消耗、明细在双端正常展示（查看不违规，支付才违规）；
   - 审核时 iOS 版本若出现虚拟支付入口会被驳回，提交审核前务必做双端检查。

### A5. 配置《用户隐私保护指引》

在 mp 后台声明收集的信息类型（手机号、孩子档案信息等），提交审核后生效。
涉及未成年人信息，指引中需明确监护人授权条款——上线前建议由法务顾问过一遍。

### A6. 完成小程序 ICP 备案 + 安装开发者工具

- 备案：mp 后台引导填写 → 平台初审 → 工信部短信核验 → 通管局审核，全程线上、免费，约 1~3 周
- 下载[微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)，用管理员微信扫码登录

**以上 6 步完成后，把 AppID 发给我，剩下的交给我。**

## B. 技术迁移方案（我来执行，拿到 AppID 后约 2~3 天）

### 推荐方案：微信云开发（CloudBase）—— 真正的「一键部署」

| 维度 | 云开发（推荐） | 自建服务器 |
|---|---|---|
| 服务器/域名 | 不需要 | 需购买 + HTTPS 证书 |
| ICP 域名备案 | **不需要**（小程序 ICP 备案仍需要） | 域名必须 ICP 备案 |
| 微信登录 | 云函数直接拿到 openid，零交换成本 | 需 code2Session 接口交换 |
| LLM 密钥 | 云函数环境变量，不出服务端 | 同级安全 |
| 成本 | 按量付费，初期几乎为 0 | 服务器固定成本 |

### 迁移映射表（现有代码 → 小程序）

| 现有（Next.js Web） | 小程序侧 | 工作量 |
|---|---|---|
| `app/*/page.tsx` 13 个页面 | Taro / 原生小程序页面，样式 token px→rpx 一一对应 | 主要工作量 |
| `app/api/*` 路由 | 云函数（`cloudfunctions/`） | 低，逻辑直接搬运 |
| `lib/agents.ts` 七专家矩阵 | 云函数内调用，Prompt 不变 | 零改动 |
| `lib/store.ts` JSON 存储 | 云数据库集合（users/profiles/sessions/reports/posts/weekly/progress） | 低，接口已收敛 |
| `data/knowledge/` RAG 语料 | 云数据库存储 + 检索逻辑不变 | 零改动 |
| `app/api/auth` 登录 | `wx.login` → 云函数取 openid 无感登录；`getPhoneNumber` 按钮组件绑定手机号 | 已有注释标记接入点 |

### 一键流程（迁移完成后你的日常操作）

```
微信开发者工具 → 导入项目 → 点「上传」→ mp 后台设为体验版（扫码即体验）
→ 提交审核（1~7 天）→ 发布上线
```

## 附：为什么登录先做「微信无感」再做「手机号」

1. 微信登录免费、零摩擦，家长打开即用——对崩溃现场想立刻演练的场景至关重要；
2. 手机号组件按次收费且有滥用回收风险，按需触发最经济；
3. 当前 Web 版 `/api/auth` 已实现完全相同的语义（openid 登录 + 验证码绑定），
   小程序迁移时只需把「dev 模拟通道」替换为 `code2Session` 调用（代码中已标注位置）。
